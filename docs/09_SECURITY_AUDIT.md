# Security audit

Git history scan inspected 4,008 historical source/config/text blobs and current tracked files against private environment secret values. One historical docs/LOGIN_ROUTE_REPAIR.md blob contains the currently configured GOOGLE_CLIENT_SECRET. Its value is deliberately not reproduced here. A database/seed_data.sql data export exists in history. Historical .env.example files were flagged for private review by filename, which alone does not establish that those templates exposed real credentials. Current tracked exact-value findings: zero.

Release blocker: review the exposed Google client secret in Google Cloud, identify any consumers, revoke/rotate it and retain only the web Client ID for this app's GIS flow. Do not rotate Razorpay keys or disrupt the shared merchant account. Privately inspect the historical SQL export for personal/configuration data. If a real secret is found there, coordinate its rotation with its owner. Public Git history cleanup, if needed, requires explicit approval and coordination; no force push/history rewrite was performed. A scan for known values cannot prove unknown/old secrets never existed.

Changes: production MySQL/config fail-closed checks; removal of automatic production seeds; configurable existing owner identity; write-only encrypted gateway secrets; authoritative pricing; Test/production fulfillment isolation; per-order locking; student-scoped data; server-side logout; CORS/origin validation; no-store API responses; nosniff/HSTS headers; persistent upload paths; restricted remote admin destination and stripped caller credentials. The old simulated checkout returns 410; failed upload cannot return a fake success. /api/question now requires student entitlement.

Production npm dependency audit: zero known vulnerabilities in installed production packages. This is not a penetration-test certificate. Dev-tool audit, full dynamic fuzzing, hostile multi-process race testing, hosted proxy behavior and normal superadmin browser actions still need broader release review. Session tokens remain bearer tokens held by the existing client; XSS prevention and dependency updates remain important. Runtime DB credentials must not have schema/drop privileges.

No actual secret appears in this report or the new environment templates. Private local environments, dumps, browser profiles and snapshots are ignored. No live student data was modified. Temporary non-admin HTTP fixtures existed only in the isolated local MySQL database and were removed by their exact IDs.

RichText previously inserted raw HTML; it now uses DOMPurify with an HTML-only profile and forbidden embedded/form content. A real-browser malicious-markup test checks removal of executable attributes/URLs while preserving Sanskrit and formatting. OTP consumption uses a single conditional database update so concurrent reuse cannot issue multiple sessions; password recovery revokes older student sessions. Admin fetch only attaches tokens to same-origin first-party APIs. The global question endpoint now requires entitlement.

The final current-tree scan also includes untracked, unignored source/configuration files. Excluded private snapshots/uploads/artifacts are not deployment source. The exposed historical Google value was not printed or automatically rotated.
